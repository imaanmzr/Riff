# Documentation

Use this guide for documentation advice or edits, or when an engineering
task changes what people need to know. Apply the
[route rubric](WORKFLOW.md#route-rubric) to the consequences of incorrect
instructions and the work needed to verify them.

1. Identify the reader and what they need to do or decide. Find the existing
   canonical page and project conventions before choosing a location.
   Use [Shared questioning](INTERVIEW.md) only for consequential missing audience,
   outcome or scope; do not turn a specified documentation edit into an interview.
2. Verify claims and examples against the source, command help, or other
   authoritative evidence. Run commands when practical and within scope.
   Flag examples that still need live verification. For example, when the
   installer supports a host omitted from setup docs, verify its CLI name,
   installation path, and invocation, then update the relevant pages.
3. Update the canonical source when an edit is requested or already in task
   scope. Add a guide for a repeatable procedure, a glossary entry for a
   recurring domain term, or an architecture decision record for a trade-off
   future maintainers need to understand. Follow existing conventions for
   each. Use short links from entry points and task records to help readers
   find the detail.
4. For advice, return concrete suggestions and their supporting evidence.
   For edits, report what changed and what verification was possible.
